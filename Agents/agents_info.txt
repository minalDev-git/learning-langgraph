# Since we are using so many different messages and tool calls, we can't append everything to the state as it would get too complicated.
A ReAct agent repeatedly reasons, calls tools when needed, and observes their results. The messages field carries the conversation between those steps.
The add_messages reducer helps keep those messages together, so the agent can see the tool results and earlier conversation when it runs again.
This lets your agent preserve the conversation as it moves through the graph.
One detail: add_messages does more than blindly append; it also handles message IDs and updates to existing messages.

AGENT 4 Drafter Agent:
The graph of agent 4 looks similar to ReAct agent but ther's a reason that we haven't chosen ReAct agent for this project.
See, we realized that one of the tools is the save tool, but obviously once we saved the draft, the process should end. However in ReAct agent, the
tools always goes back to the agent(llm), not directly to the end point. We don't want taht here. So that's why, as soon as the "save" tool is used,
the graph ends.

We defined a global variable "document_content" to actually pass in the state in tools. The correct way to do this in LangGraph is to use Inject State.
What will happen here is, whatever updates are made our tools will update the global variable. ANd then we are going to save the draft, the save tool will
use the contents of this global variable and save that into a text file.

From tools node there's going to be a choice of either going back to the agent or going to the End node
